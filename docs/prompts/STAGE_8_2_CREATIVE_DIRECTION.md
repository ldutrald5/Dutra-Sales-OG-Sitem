## Mission

Transform the OG proposal from a correct document into a memorable commercial experience.

## 10-second objective

The decision-maker should quickly understand:
- who the proposal is for;
- scale/context of the operation;
- what OG is solving;
- investment;
- strongest value signal;
- next step.

Do not force long technical reading before interest is created.

## Create 3 genuinely different directions

### A — IMPACT OG
Bold, memorable, commercial, large numbers, strong contrast, distinctive personality.

### B — EXECUTIVE PREMIUM
Refined, elegant, sophisticated, lower visual noise, high perceived value.

### C — OPERATIONAL STORYTELLING
Narrative flow: scenario → problem/opportunity → OG application → investment → economic impact → next step.

These must differ in composition and narrative, not only color.

## For each direction define

- EMOTIONAL TARGET
- FIRST IMPRESSION
- HERO
- COLOR / CONTRAST
- TYPOGRAPHY FEEL
- STORY RHYTHM
- BLOCK/CARD LANGUAGE
- IMAGERY
- MAIN DATA EMPHASIS
- CAVALO × CARRETA PRESENTATION
- ROI PRESENTATION
- INVESTMENT PRESENTATION
- CTA / NEXT STEP
- MOBILE
- DESKTOP
- PDF / PNG BEHAVIOR
- WHAT MAKES IT DISTINCTIVE
- RISKS
- WHAT NOT TO DO
- WHAT MUST REMAIN EASY TO EDIT LATER

## Fair comparison

Use the same controlled proposal data in all three directions.

No concept may change:
- client identity;
- vehicles;
- quantities;
- pricing;
- technical application;
- ROI math/premises;
- proposal status semantics.

## Lightweight first-impression test

For each concept answer:

- What does a viewer likely notice first?
- What would they remember after 5 seconds?
- Is the value understood?
- Does it feel premium / distinctive?
- Is the next action obvious?
- Is information density appropriate?
- What is hidden until deeper inspection?

## Do not choose automatically

Present A / B / C for Lucas to:
- choose;
- reject;
- combine;
- annotate.

Capture WHY.

## After Lucas chooses

Only then:
1. compile selected Design DNA;
2. define semantic design tokens;
3. define reusable story blocks;
4. define template configuration schema;
5. prototype first viewport + mid-story + deep-detail + CTA;
6. prepare the implementation prompt.

Do not broad-code before selection.
