# Minimal Context Routing

The second brain is useful only if it reduces repeated reasoning rather than flooding context.

## Load by task

| Task | Load first |
|---|---|
| Product direction | vision + active decisions + roadmap |
| Bug/fix | relevant module + tests + related decision only |
| Data change | domain/data architecture + migration rules + affected entities |
| UI/UX | workflow + design tokens + affected domain |
| External reference | source question + current analogous problem + source intake template |
| AI feature | AI boundary + knowledge items + affected entity/service |
| Implementation package | package plan + decisions + affected code + baseline |
| Post-release learning | package report + user friction + brain index |

## Compression rule

Prefer durable summaries with IDs over raw historical conversations. Preserve raw source links/paths for drill-down.

## Staleness rule

When a brain entry conflicts with current code/runtime evidence, current evidence wins. Mark the old entry superseded rather than deleting history.
