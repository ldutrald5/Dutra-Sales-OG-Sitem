# Context-Aware Idea Engine

The goal is not maximum idea count. It is maximum useful leverage per unit of complexity.

## Triggers for idea generation

Generate ideas when:

- repeated friction appears in real use;
- an external source reveals a transferable pattern;
- a new canonical entity unlocks product value;
- a package removes a technical constraint;
- data reveals a workflow bottleneck;
- the user explicitly asks to brainstorm.

## Idea card

For every non-trivial idea record:

- title
- trigger/evidence
- user/problem
- proposed capability
- data/entities touched
- dependencies
- smallest useful version
- what not to build yet
- visible user value
- qualitative complexity
- regression/migration risk
- confidence
- suggested horizon: NOW / NEXT / LATER / REJECT

## Idea filters

Kill or defer an idea when:

- it creates a second source of truth;
- it needs infrastructure that does not solve a current problem;
- the user workflow does not materially improve;
- the same value can be obtained deterministically with less complexity;
- required data does not exist or is unreliable;
- it would force a broad rewrite to deliver a small benefit.

## Idea synthesis from external references

Never say “Deskcomm has X, so we need X.”

Use:

`Observed pattern → problem solved there → our analogous problem → applicability → simplified adaptation → smallest experiment`.

## Professional polish ideas

Small UX details can be high leverage when they reduce hesitation or clicks:

- save/sync truth states;
- quick actions;
- copy buttons;
- next-action badges;
- keyboard/touch paths;
- inline validation;
- meaningful empty states;
- visible ownership/status;
- consistent labels/components;
- fast side panels rather than navigation churn.

Treat polish as part of workflow design, not decoration.
